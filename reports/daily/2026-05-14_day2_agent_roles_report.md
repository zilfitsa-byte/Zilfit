## 3. Z-Product

Z-Product مسؤول عن تحويل حالة المشروع إلى أولويات منتج قابلة للتنفيذ. لا يقرر جاهزية الإنتاج ولا يغيّر ملفات حساسة. دوره الأساسي هو ترتيب الأولويات، تحديد العوائق، وتحويل نتائج الوكلاء الآخرين إلى قرارات واضحة تحتاج أو لا تحتاج موافقة سلطان.

الحدود الأساسية:
- لا قرارات إنتاج نهائية.
- لا ادعاءات طبية.
- لا تعديل demo أو bot أو proxy أو auth أو API keys أو cron أو systemd أو production tunnels أو main branch.
- لا شراكات أو مستثمرين قبل نجاح عينة إنتاج ملموسة.

---

## 4. Z-Claims

Z-Claims مسؤول عن فحص اللغة والمطالبات. هدفه منع أي عبارة توحي بتشخيص أو علاج أو فعالية سريرية أو مطالبة طبية. هذا الدور لا يراجع طبيًا، بل يحرس اللغة والامتثال الداخلي.

المصطلحات عالية الخطورة تشمل:
- تشخيص.
- علاج.
- وقاية.
- تخفيف الألم.
- فعالية سريرية.
- مطالبة طبية.
- clinical efficacy.
- medical claim.
- diagnosis.
- treatment.

البدائل المقبولة:
- تقدير هندسي.
- فرضية تصميم.
- مخرج داخلي.
- متطلب عينة.
- مراجعة متخصصة مطلوبة.

## 5. أثر الإضافة على منظومة ZILFIT

بعد إضافة Z-Product و Z-Claims، تصبح دورة اليوم الأساسية أوضح:

1. Z-Ops يقرأ الحالة والتقارير والمهام.
2. Z-QA يفحص الجودة والمخاطر التشغيلية.
3. Z-Research يحوّل الأدلة إلى ملخصات داخلية غير إنتاجية.
4. Z-Product يحوّل الحالة إلى أولويات.
5. Z-Claims يمنع تضخم اللغة والمطالبات الطبية.

هذا يقلل الخلط بين البحث والهندسة والادعاءات، ويجعل كل تقرير يومي أكثر قابلية للمراجعة.
